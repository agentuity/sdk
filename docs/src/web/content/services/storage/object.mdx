Use object storage for files, images, documents, media, backups, and other data that belongs outside your database. Agentuity exposes storage buckets through S3-compatible credentials, and Bun apps can use Bun's native `s3` APIs directly.

```typescript
import { s3 } from 'bun';

const file = s3.file('reports/monthly-summary.json');

await file.write(JSON.stringify({ month: '2026-04', total: 42817 }), {
  type: 'application/json',
});

const summary = (await file.exists()) ? await file.json() : undefined;
```

`s3.file()` creates a lazy file reference. Network work starts when you read, write, check existence, delete, or stream the file.

<Callout type="info" title="Object storage is Bun-native">
The examples on this page use Bun's `s3` and `S3Client` APIs. In a non-Bun server process, use that runtime's S3-compatible client with the same bucket credentials.
</Callout>

## Setup

Object storage requires a storage bucket linked to your project.

```bash
agentuity cloud storage create --name app-uploads
agentuity project add storage app-uploads
```

`agentuity cloud storage create` writes bucket credentials to `.env` when you run it from a project directory. `agentuity project add storage` links an existing bucket to the current project and writes the same credentials.

The credentials written to `.env` are:

- `S3_ACCESS_KEY_ID`
- `S3_SECRET_ACCESS_KEY`
- `S3_BUCKET`
- `S3_ENDPOINT`

<Callout type="warning" title="Keep S3 credentials on the server">
Do not expose bucket credentials to browser code. Create presigned URLs from a server route when a browser needs direct upload or download access.
</Callout>

## When to Use Object Storage

| Need | Use |
|------|-----|
| files or binary data | [Object Storage](/services/storage/object) |
| exact key lookup | [Key-Value](/services/storage/key-value) |
| semantic search or RAG retrieval | [Vector](/services/storage/vector) |
| generated output readable by URL | [Durable Streams](/services/storage/durable-streams) |
| relational joins or transactions | [Database](/services/database) |

## Read, Write, and Delete

Use the global `s3` client when your app uses the bucket credentials from the environment.

```typescript
import { s3 } from 'bun';

const avatar = s3.file('users/user_123/avatar.png');

await avatar.write(await fetch('https://example.com/avatar.png'), {
  type: 'image/png',
});

if (await avatar.exists()) {
  const bytes = await avatar.bytes();
  const contentType = avatar.type;
  // bytes is Uint8Array; contentType is the stored MIME type
  void bytes;
  void contentType;
}

await avatar.delete();
```

For large files, write incrementally instead of holding the whole payload in memory:

```typescript
import { s3 } from 'bun';

const file = s3.file('exports/large-report.csv');
const writer = file.writer({
  type: 'text/csv',
  partSize: 5 * 1024 * 1024,
  queueSize: 4,
});

writer.write('account_id,total\n');
writer.write('acct_123,42817\n');
await writer.end();
```

## Presigned URLs

Generate presigned URLs from server code when clients should upload or download directly.

```typescript
import { s3 } from 'bun';

const downloadUrl = s3.presign('reports/monthly-summary.json', {
  method: 'GET',
  expiresIn: 60 * 15,
});

const uploadUrl = s3.presign('uploads/invoice.pdf', {
  method: 'PUT',
  expiresIn: 60 * 10,
  type: 'application/pdf',
});
```

`presign()` is synchronous. It signs a URL from local credentials and does not call S3.

## Uploads from a Hono Route

Keep browser uploads direct to S3 by returning a short-lived upload URL from your backend.

```typescript title="src/index.ts"
import { s } from '@agentuity/schema';
import { s3 } from 'bun';
import { Hono } from 'hono';

const uploadRequestSchema = s.object({
  filename: s.string(),
  contentType: s.string(),
});

const app = new Hono();

app.post('/api/uploads/presign', async (c) => {
  const body: unknown = await c.req.json();
  const input = uploadRequestSchema.parse(body);
  const key = `uploads/${crypto.randomUUID()}-${input.filename}`;

  const url = s3.presign(key, {
    method: 'PUT',
    expiresIn: 60 * 10,
    type: input.contentType,
  });

  return c.json({ key, url });
});

app.get('/api/uploads/download', async (c) => {
  const key = c.req.query('key');

  if (!key) {
    return c.json({ error: 'Missing key' }, 400);
  }

  const file = s3.file(key);

  if (!(await file.exists())) {
    return c.json({ error: 'File not found' }, 404);
  }

  return new Response(file);
});

export default app;
```

Passing an `S3File` to `new Response()` returns a redirect to a presigned download URL, so the file does not flow through your route process.

## Custom S3 Clients

Use `S3Client` when you need a specific bucket, external S3-compatible service, or explicit credentials.

```typescript
import { S3Client } from 'bun';

function requireEnv(name: string): string {
  const value = process.env[name];

  if (!value) {
    throw new Error(`${name} is required`);
  }

  return value;
}

const uploads = new S3Client({
  accessKeyId: requireEnv('S3_ACCESS_KEY_ID'),
  secretAccessKey: requireEnv('S3_SECRET_ACCESS_KEY'),
  bucket: requireEnv('S3_BUCKET'),
  endpoint: requireEnv('S3_ENDPOINT'),
  region: 'auto',
});

await uploads.write('healthcheck.txt', 'ok', { type: 'text/plain' });
```

For Agentuity-managed buckets, prefer the environment variables written by the CLI. For other providers, pass that provider's endpoint, bucket, and credentials to `S3Client`.
