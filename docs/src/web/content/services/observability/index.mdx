## Quick Reference

| Need | Use |
|------|-----|
| application logs | stdout/console, structured logger, or `logger` from `@agentuity/telemetry` |
| route logs in Hono | `c.var.logger` from `@agentuity/hono` |
| custom spans | OpenTelemetry API, `tracer` from `@agentuity/telemetry`, or `c.var.tracer` in Hono |
| eval runs | your test runner, output contracts, traces, and optional hosted eval tooling |
| request/session history | `agentuity cloud session` and the Agentuity Console |
| deployment output | `agentuity cloud deployment logs` |
| browser page views and events | `@agentuity/analytics` when a collect endpoint is configured, or your framework analytics tool |

## Access Patterns

| App Shape | Logging | Tracing | Analytics |
|-----------|---------|---------|-----------|
| Any server framework or script | stdout/console, your structured logger, or `logger` from `@agentuity/telemetry` | your OpenTelemetry setup or `tracer` from `@agentuity/telemetry` | framework analytics or `@agentuity/analytics` |
| Hono with `@agentuity/hono` | `c.var.logger` | `c.var.tracer` | framework analytics or `@agentuity/analytics` |
| CLI and Console inspection | session and deployment log commands | session timeline views | session and deployment views |

```bash
bun add @agentuity/telemetry@next
```

```typescript
import { logger, tracer } from '@agentuity/telemetry';

logger.child({ route: 'POST /api/chat' }).info('Request received');

await tracer.startActiveSpan('load-context', async (span) => {
  try {
    span.setAttribute('source', 'kv');
    return { ready: true };
  } finally {
    span.end();
  }
});
```

`@agentuity/telemetry` reads Agentuity environment variables when they are present. Use explicit `register()` options when the code runs outside an Agentuity project or you want to set service metadata yourself.

## Choose a Telemetry Path

| Path | Use when |
|------|----------|
| `@agentuity/telemetry` | you want Agentuity defaults for logger, tracer, meter, and OTLP export setup |
| `@agentuity/hono` | your Hono routes should receive Agentuity clients and telemetry through `c.var.*` |
| Bring-your-own OpenTelemetry | you already have a collector, vendor SDK, or framework instrumentation |
| stdout or framework logger | you only need process logs and your existing log pipeline already captures them |

OpenTelemetry JavaScript traces and metrics are stable. The OpenTelemetry JavaScript logs signal is still marked development by the upstream project, so keep log pipelines simple: stdout or a structured logger is still a reasonable default, and telemetry logs should be treated as part of your chosen exporter path.

## Hono Middleware

Hono apps can install one middleware to initialize telemetry and inject Agentuity services into `c.var`.

```bash
bun add @agentuity/hono@next @opentelemetry/api hono
```

```typescript
import { Hono } from 'hono';
import { agentuity } from '@agentuity/hono';
import type { Logger } from '@agentuity/hono';
import type { Tracer } from '@opentelemetry/api';

interface Env {
  readonly Variables: {
    readonly logger: Logger;
    readonly tracer: Tracer;
  };
}

const app = new Hono<Env>();

app.use('*', agentuity({ telemetry: { logLevel: 'info' } }));

app.get('/health', (c) => {
  c.var.logger.info('Health check');
  return c.json({ ok: true });
});

export default app;
```

## Sessions

Sessions are platform observability records. The v3 framework docs do not teach runtime `ctx.session` or `ctx.thread` as the default app API, but the CLI and Console can inspect session records created by deployed or dev-mode framework requests when that data is available.

```bash
agentuity cloud session list
agentuity cloud session get sess_abc123xyz
agentuity cloud session logs sess_abc123xyz
```

<Callout type="info" title="Session records are not app sessions">
Use your framework or auth provider for user sessions. Agentuity session records are observability records used for debugging requests, logs, and traces.
</Callout>
