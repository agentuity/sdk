## Quick Reference

| Need | Use |
|------|-----|
| application logs | [Pino app logs](/cookbook/patterns/structured-logging-with-pino), [LogTape logs](/cookbook/patterns/logtape-structured-logging), your framework logger, or `logger` from `@agentuity/telemetry` |
| route logs in Hono | `c.var.logger` from `@agentuity/hono` |
| custom spans | [OpenTelemetry API spans](/cookbook/patterns/opentelemetry-route-spans), [Langfuse traces](/cookbook/patterns/langfuse-otel-tracing), `tracer` from `@agentuity/telemetry`, or `c.var.tracer` in Hono |
| eval runs | your test runner, output contracts, traces, [OpenAI Evals API](/cookbook/patterns/openai-evals-api), or [Braintrust Evals](/cookbook/patterns/braintrust-evals) |
| request/session history | `agentuity cloud session` and the Agentuity Console |
| deployment output | `agentuity cloud deployment logs` |
| browser page views and events | `@agentuity/analytics` when a collect endpoint is configured, or your framework analytics tool |

## Access Patterns

| App Shape | Logging | Tracing | Analytics |
|-----------|---------|---------|-----------|
| Any server framework or script | stdout through Pino, your structured logger, or `logger` from `@agentuity/telemetry` | your OpenTelemetry setup or `tracer` from `@agentuity/telemetry` | framework analytics or `@agentuity/analytics` |
| Hono with `@agentuity/hono` | `c.var.logger` | `c.var.tracer` | framework analytics or `@agentuity/analytics` |
| CLI and Console inspection | session and deployment log commands | session timeline views | session and deployment views |

```bash
npm install @agentuity/telemetry@next
```

```typescript
import { logger, tracer } from '@agentuity/telemetry';

logger.child({ route: 'POST /api/chat' }).info('Request received');

await tracer.startActiveSpan('load-context', async (span) => {
  try {
    span.setAttribute('source', 'kv');
    return { ready: true };
  } finally {
    span.end();
  }
});
```

`@agentuity/telemetry` reads Agentuity environment variables when they are present. Use explicit `register()` options when the code runs outside an Agentuity project or you want to set service metadata yourself.

## Choose a Telemetry Path

| Path | Use when |
|------|----------|
| `@agentuity/telemetry` | you want Agentuity defaults for logger, tracer, meter, auto-instrumentation, and OTLP export setup |
| `@agentuity/hono` | Hono routes receive Agentuity clients and telemetry through `c.var.*` |
| [Bring-your-own OpenTelemetry](/cookbook/patterns/opentelemetry-route-spans) | a framework plugin, collector, or vendor SDK already owns telemetry startup |
| [Langfuse tracing](/cookbook/patterns/langfuse-otel-tracing) | Langfuse already owns LLM trace review for the app |
| [Pino or LogTape logger](/services/observability/logging) | your existing log pipeline already captures process output |

OpenTelemetry is useful for timing and cross-service context, but it does not need to be the center of every app. OpenTelemetry JavaScript traces and metrics are stable, while the JavaScript logs signal is still marked development by the upstream project. Normal stdout or structured logging remains a reasonable log path.

## Hono Middleware

Hono apps can install one middleware when `c.var.*` is the cleanest injection point for shared Agentuity clients and telemetry defaults.

```bash
npm install @agentuity/hono@next @opentelemetry/api hono
```

```typescript
import { Hono } from 'hono';
import { agentuity } from '@agentuity/hono';
import type { Logger } from '@agentuity/hono';
import type { Tracer } from '@opentelemetry/api';

interface Env {
  readonly Variables: {
    readonly logger: Logger;
    readonly tracer: Tracer;
  };
}

const app = new Hono<Env>();

app.use('*', agentuity({ telemetry: { logLevel: 'info' } }));

app.get('/health', (c) => {
  c.var.logger.info('Health check');
  return c.json({ ok: true });
});

export default app;
```

## Sessions

Sessions and deployment logs are Agentuity inspection surfaces. Use them to move from an app failure to the request or session timeline, deployment output, logs, and traces when that data is available.

```bash
agentuity cloud session list
agentuity cloud session get sess_abc123xyz
agentuity cloud session logs sess_abc123xyz
```

<Callout type="info" title="Session records are not app sessions">
Use your framework or auth provider for user sessions. Agentuity session records are observability records used for debugging requests, logs, and traces.
</Callout>
