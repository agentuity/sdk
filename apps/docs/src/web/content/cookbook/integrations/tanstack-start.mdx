Already have a [TanStack Start](https://tanstack.com/start/latest/docs/framework/react/overview) app? Add Agentuity agents alongside your existing frontend for agent-native infrastructure: persistent state, storage, observability, and an AI gateway. The two services run side by side, connected through a Vite proxy.

## Project Structure

The Agentuity backend lives in an `agentuity/` subdirectory inside your TanStack Start project:

```text
my-tanstack-app/
├── src/
│   ├── router.tsx                  # Route registration
│   ├── routes/__root.tsx           # Root shell
│   └── routes/index.tsx            # UI using hc() for type-safe API calls
├── agentuity/                      # Agentuity backend
│   ├── src/agent/translate/        # Agent with handler + evals
│   ├── src/api/index.ts            # HTTP routes
│   └── src/generated/routes.ts     # Generated route types
├── vite.config.ts                  # /api proxy to backend
└── tsconfig.json                   # @agentuity/routes alias
```

## Vite Proxy Configuration

Vite's built-in proxy forwards `/api` requests to the Agentuity backend during development:

```typescript title="vite.config.ts"
import { defineConfig } from 'vite';
import tsconfigPaths from 'vite-tsconfig-paths';
import { tanstackStart } from '@tanstack/react-start/plugin/vite';

export default defineConfig({
  plugins: [tsconfigPaths(), tanstackStart()],
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:3500', // [!code highlight]
        changeOrigin: true,
      },
    },
  },
  ssr: {
    // Keep Agentuity packages bundled for SSR compatibility
    noExternal: [/^@agentuity\//],
  },
});
```

<Callout type="info" title="Two runtimes in development">
`bun run dev` starts both the TanStack Start frontend and the Agentuity backend concurrently. The frontend waits for the backend health check before launching Vite.
</Callout>

## Path Alias Setup

Add the `@agentuity/routes` alias in `tsconfig.json` so TypeScript resolves the generated route types:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "paths": {
      "@agentuity/routes": ["./agentuity/src/generated/routes"]
    }
  }
}
```

## Type-Safe API Calls

Import the route types and use `hc()` from `hono/client` for type-safe requests:

```tsx title="src/routes/index.tsx"
import { AgentuityProvider } from '@agentuity/react';
import { hc } from 'hono/client'; // [!code highlight]
import type { ApiRouter } from '@agentuity/src/api'; // [!code highlight]
import { useState, useEffect } from 'react';

const client = hc<ApiRouter>(import.meta.env.VITE_AGENTUITY_BASE_URL); // [!code highlight]

function TranslateDemo() {
  const [data, setData] = useState<{ translation: string } | null>(null);
  const [isLoading, setIsLoading] = useState(false);

  const onTranslate = async () => {
    setIsLoading(true);
    const res = await client.api.translate.$post({ json: { text: 'Hello world', toLanguage: 'French' } }); // [!code highlight]
    setData(await res.json());
    setIsLoading(false);
  };

  return (
    <div>
      <button onClick={onTranslate} disabled={isLoading}>Translate</button>
      {data?.translation && <p>{data.translation}</p>}
    </div>
  );
}
```

The `hc()` client provides type-safe API calls from your route definitions. `AgentuityProvider` wraps at the route level via `createFileRoute`, and you use `import.meta.env.VITE_AGENTUITY_BASE_URL` for the backend URL.

<Callout type="tip" title="SSR and noExternal">
The `ssr.noExternal` setting in `vite.config.ts` keeps `@agentuity/*` packages bundled during server-side rendering. Without it, Vite may try to externalize them and fail to resolve browser-only imports.
</Callout>

## Running Locally

Run from the project root (not from inside `agentuity/`):

```bash
bun install
bun run build:agent    # Generate route types
bun run dev            # Start both runtimes
```

- Frontend: `http://localhost:3000`
- Backend: `http://localhost:3500`
- Workbench: `http://localhost:3500/workbench`

## Deployment

When deployed, configure routing at the host level:

1. **Preferred**: Route `/api/*` traffic to the Agentuity backend at the load balancer, matching the local Vite proxy behavior.
2. **Fallback**: Set `VITE_AGENTUITY_BASE_URL` to the backend URL and pass it through `AgentuityProvider baseUrl`. Enable CORS with `AGENTUITY_CORS_ALLOWED_ORIGINS` on the backend.
