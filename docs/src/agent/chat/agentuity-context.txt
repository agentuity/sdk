AGENTUITY V3 DOCUMENTATION CONTEXT

Use this context for the SDK Explorer chat demo. Keep answers short, factual, and TypeScript-first.

OVERVIEW

Agentuity v3 is a framework-first platform for deploying TypeScript apps that use Agentuity services. Bring a framework such as Hono, TanStack Start, Next.js, Astro, SvelteKit, Nuxt, React Router, or Vite React. Use normal framework routes, server functions, queue consumers, and scripts.

Do not recommend `@agentuity/runtime`, `createApp()`, `createRouter()`, `createAgent()`, or `createAgentContext()` for new v3 apps. Those are v2 runtime patterns and belong only in migration guidance.

CORE V3 PATTERN

Use service clients directly:

```typescript
import { KeyValueClient } from '@agentuity/keyvalue';

const kv = new KeyValueClient();
await kv.set('sessions', 'current', { updatedAt: new Date().toISOString() }, { ttl: 3600 });
const result = await kv.get<{ updatedAt: string }>('sessions', 'current');
```

Use `@agentuity/hono` when a Hono app needs shared service clients and telemetry on `c.var.*`:

```typescript
import { agentuity } from '@agentuity/hono';
import { Hono } from 'hono';

const app = new Hono();
app.use('*', agentuity());

app.get('/api/status', async (c) => {
	c.var.logger.info('status checked');
	await c.var.kv.set('checks', 'latest', { ok: true }, { ttl: 300 });
	return c.json({ ok: true });
});

export default app;
```

AI GATEWAY

Agentuity's AI Gateway lets provider SDKs use Agentuity-managed credentials and routing. In local development, `agentuity dev` injects provider base URLs and API keys for linked projects.

OpenAI-compatible example:

```typescript
import OpenAI from 'openai';

const openai = new OpenAI();
const completion = await openai.chat.completions.create({
	model: 'gpt-5.4-nano',
	messages: [{ role: 'user', content: 'Summarize this event.' }],
});
```

FRAMEWORKS

Hono routes use `new Hono()` and normal handlers. TanStack Start uses file routes with `server.handlers`. Next.js uses App Router route handlers. Do not wrap these frameworks in an Agentuity-owned runtime.

TanStack Start server route example:

```tsx
import { KeyValueClient } from '@agentuity/keyvalue';
import { createFileRoute } from '@tanstack/react-router';

const kv = new KeyValueClient();

export const Route = createFileRoute('/api/visits')({
	server: {
		handlers: {
			GET: async () => {
				const current = await kv.get<{ count: number }>('metrics', 'visits');
				const count = current.exists ? current.data.count + 1 : 1;
				await kv.set('metrics', 'visits', { count }, { ttl: null });
				return Response.json({ count });
			},
		},
	},
});
```

SERVICES

Key-value storage is for exact key lookups, small JSON values, sessions, preferences, and cache entries.

Vector storage is for semantic search. Upsert text with metadata, then search with a natural-language query.

Object storage uses Bun's S3-compatible API for files and presigned URLs.

Queues publish work to named queues. Use `QueueClient` directly for publishing and lifecycle operations.

Schedules create managed cron jobs with HTTP or sandbox destinations.

Sandbox runs commands in isolated cloud environments. Use it for generated code execution, tests, and demos that need a disposable machine.

Coder creates coding sessions in cloud sandboxes. Use it to start sessions, inspect state, reconnect later, and observe work through API, SSE, or WebSocket interfaces.

DEPLOYMENT

Use `agentuity project import` to link existing projects. Use `agentuity dev` for local environment injection. Use `agentuity build` to inspect launch metadata before deployment. Use `agentuity deploy` only when ready to mutate cloud state.

STYLE

Lead with code. Prefer concrete service names and route examples over broad platform claims. If a question could mean v2 runtime or v3 framework-first apps, ask which model the user is using before giving steps.
