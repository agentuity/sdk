Use `@agentuity/postgres` when Bun server code explicitly wants the Agentuity helper around direct SQL access through `DATABASE_URL`. The client wraps Bun's native SQL driver and adds reconnect behavior around connection loss.

```bash
bun add @agentuity/postgres@alpha
```

```typescript
import { postgres } from '@agentuity/postgres';

const sql = postgres();

const users = await sql`
  SELECT id, email
  FROM users
  WHERE active = ${true}
`;
```

<Callout type="info" title="This client is Bun-native">
`@agentuity/postgres` imports Bun's SQL driver. Use it in Bun-based Agentuity apps and scripts that choose this helper. In other Node.js processes, use your framework's Postgres client, ORM, or the `@agentuity/db` service client for trusted admin scripts.
</Callout>

## Connection Setup

`postgres()` reads `DATABASE_URL` by default. You can also pass a connection URL or a configuration object.

```typescript
import { postgres } from '@agentuity/postgres';

const sql = postgres({
  url: process.env.DATABASE_URL,
  max: 10,
  prepare: false,
  reconnect: {
    enabled: true,
    maxAttempts: 10,
    initialDelayMs: 100,
    maxDelayMs: 30_000,
  },
});
```

Leave `prepare: false` when your database connection may pass through a connection pooler.

## Transactions

Transactions group related queries so they succeed or roll back together. The transaction object is not callable: use `tx.query` for tagged-template queries inside the transaction.

```typescript
const tx = await sql.begin();

try {
  await tx.query`UPDATE accounts SET balance = balance - ${100} WHERE name = ${'Alice'}`;
  await tx.query`UPDATE accounts SET balance = balance + ${100} WHERE name = ${'Bob'}`;
  await tx.commit();
} catch (error) {
  await tx.rollback();
  throw error;
}
```

Pass transaction options when you need a specific isolation level.

```typescript
const tx = await sql.begin({
  isolationLevel: 'serializable',
  readOnly: true,
  deferrable: true,
});
```

Use savepoints when only part of the transaction should roll back.

```typescript
const tx = await sql.begin();

try {
  await tx.query`INSERT INTO users (name) VALUES (${'Alice'})`;

  const savepoint = await tx.savepoint();

  try {
    await tx.query`INSERT INTO users (name) VALUES (${'Bob'})`;
    throw new Error('Rollback Bob only');
  } catch {
    await savepoint.rollback();
  }

  await tx.commit();
} catch (error) {
  await tx.rollback();
  throw error;
}
```

## Connection Options

| Option | Default | Description |
|--------|---------|-------------|
| `url` | `DATABASE_URL` | PostgreSQL connection string |
| `hostname`, `port`, `username`, `password`, `database` | none | Individual connection fields when not using `url` |
| `max` | `10` | Maximum connections in the pool |
| `preconnect` | `false` | Run a test query during client creation instead of connecting lazily |
| `prepare` | `false` | Use named prepared statements |
| `bigint` | `false` | Return large integers as `BigInt` instead of strings |
| `maxLifetime` | `0` | Maximum connection lifetime in seconds. `0` disables the limit |
| `reconnect.enabled` | `true` | Enable automatic reconnection |
| `reconnect.maxAttempts` | `10` | Maximum reconnection attempts |
| `reconnect.initialDelayMs` | `100` | Initial delay before first retry |
| `reconnect.maxDelayMs` | `30000` | Maximum delay between retries |

The client also supports callbacks such as `onclose`, `onreconnect`, `onreconnected`, and `onreconnectfailed`.

## Connection Stats

Use `sql.stats` when you need to inspect connection state, for example from a health route.

```typescript
const stats = sql.stats;

if (stats.reconnecting) {
  // surface this to your health endpoint or logger
}
```

| Property | Description |
|----------|-------------|
| `connected` | Whether the client is currently connected |
| `reconnecting` | Whether a reconnect attempt is in progress |
| `totalConnections` | Total successful connections |
| `reconnectAttempts` | Current reconnect attempt count |
| `failedReconnects` | Total failed reconnect attempts |
| `lastConnectedAt` | Last successful connection time |
| `lastDisconnectedAt` | Last disconnection time |
| `lastReconnectAttemptAt` | Last reconnect attempt time |

## Utility Methods

Wait for a lazy connection to be established:

```typescript
await sql.waitForConnection(5_000);
```

Shut down without starting new reconnect attempts:

```typescript
sql.shutdown();
await sql.close();
```

Run a raw SQL string with retry behavior. `unsafeQuery` retries transient errors and wraps mutations (`INSERT`, `UPDATE`, `DELETE`, `MERGE`, `CALL`, `DO`, `COPY`, `TRUNCATE`) in a transaction so retries do not double-apply.

```typescript
const version = await sql.unsafeQuery('SELECT version()');

const inserted = await sql.unsafeQuery(
  'INSERT INTO items (name) VALUES ($1) RETURNING *',
  ['demo-item']
);

const arrays = await sql.unsafeQuery('SELECT id, name FROM items').values();
```

Each `unsafeQuery` result can be consumed once, either as row objects (`await result`) or as raw arrays (`await result.values()`), not both. For dynamic values prefer tagged templates; reach for `unsafeQuery` when the SQL itself is built from a trusted source.
