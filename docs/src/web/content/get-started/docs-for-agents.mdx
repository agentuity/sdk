Use this page when Codex, Cursor, Claude Code, Devin, OpenCode, or another coding agent needs Agentuity context. Start with the markdown index, fetch only the pages for the task, then use the CLI's AI-facing commands before mutating a project.

```text
https://agentuity.dev/llms.txt
https://agentuity.dev/get-started/agent-driven-setup.md
```

## Retrieval Surfaces

| Surface | Use it when |
| --- | --- |
| `https://agentuity.dev/llms.txt` | the agent needs a compact map of the docs and links to page-level markdown |
| `https://agentuity.dev/<path>.md` | the agent already knows the exact task area |
| page copy dropdown | a human wants to copy the current page as markdown or open it in ChatGPT or Claude |
| `agentuity ai intro` | the agent is about to create, import, build, or deploy an Agentuity app |

The `.md` pages are generated from the MDX docs during the docs build. They are intended to be readable without the sidebar, search UI, or client-side navigation.

For task-oriented agent work, do not start with the all-pages export. It is large enough to hide the boundaries that matter. Fetch the compact index first, then the page-level markdown for the task.

## Start an Agent Session

Give the agent a task, the docs surface to fetch, and the approval boundary:

```text
You are working in an existing app that may be deployed on Agentuity.

1. Fetch https://agentuity.dev/llms.txt.
2. Fetch the page-level .md files for the framework and service you need.
3. Run `agentuity ai intro` before changing files.
4. Inspect the app's framework, package manager, and existing env files.
5. Add only the requested Agentuity service client.
6. Run the app's normal checks plus `agentuity project import --validate-only`
   and `agentuity build` when the project is ready.
7. Stop before deploy, domain changes, deletes, or credential creation.
```

For greenfield setup, point the agent at [Agentic Setup](/get-started/agent-driven-setup): it gives a setup report shape and stop conditions. For an existing app, point it at [Add Agentuity to an existing app](/get-started/import-existing-app): it starts from app inspection and validation instead of a fresh scaffold.

## Use the CLI for Current Shape

Docs give the task model. The CLI gives the current command shape.

```bash
agentuity ai intro
agentuity ai capabilities show
agentuity ai schema show
agentuity ai prompt llm
```

Use `agentuity ai intro` first for project setup tasks. Use `agentuity ai schema show` when an agent needs machine-readable command names, options, and requirements. Use `agentuity ai prompt llm` for broad CLI safety context, not as a replacement for a task-specific prompt.

See [AI Commands](/reference/cli/ai-commands): the command reference for AI-facing CLI output.

## Stop Before

| Situation | What the agent should do |
| --- | --- |
| `agentuity deploy`, domain changes, resource deletes, or remote project mutation | report the exact command and wait for approval |
| missing org ID, API key, setup token, provider key, or project name | ask the human; do not invent values |
| CLI `--help` disagrees with a page | trust live help for the command, then report the docs mismatch |
| framework build fails before Agentuity packaging | fix or report the app build first |
| a runtime, provider, model, or Coder artifact path is not verified | record the gap and ask before adding a claim |

## No Docs MCP Yet

Agentuity currently ships `llms.txt`, page-level `.md` files, and AI-facing CLI commands. Do not assume there is a public docs MCP server or installable docs skill unless a current Agentuity page announces one.
