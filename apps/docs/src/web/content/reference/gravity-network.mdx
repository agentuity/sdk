The Gravity Network is Agentuity's infrastructure layer for platform services. It is organized as primitives that lower layers expose and higher layers combine.

## Layered Architecture

Agentuity is built on a layered primitive model. Each layer provides building blocks for the layers above it.

### Core Primitives

At the foundation, we have core primitives that nearly everything else is built upon:

| Primitive | Purpose | Examples |
| --------- | ------- | -------- |
| **Storage** | S3-compatible object storage | File uploads, snapshots, assets |
| **Postgres** | Transactional database | Metadata, state, configuration |
| **Compute** | Agent runtime and sandboxes | Agent execution, isolated code runs |
| **OLAP Warehouse** <span className="text-xs text-zinc-500 ml-1">(coming soon)</span> | Analytical database | Logs, metrics, analytics |

These core primitives are intentionally generic and protocol-based. Storage speaks S3. Databases speak standard wire protocols.

### Platform Primitives

On top of the core primitives, we build higher-level platform primitives:

| Primitive | Built On | Purpose |
| --------- | -------- | ------- |
| <Database className="inline w-4 h-4 mr-1" /> [**Database**](/services/database) | Postgres | Managed database access |
| <DatabaseZap className="inline w-4 h-4 mr-1" /> [**Key Value**](/services/storage/key-value) | Postgres | State storage by key |
| <BookText className="inline w-4 h-4 mr-1" /> [**Vector**](/services/storage/vector) | Postgres | Semantic search |
| <ListTodo className="inline w-4 h-4 mr-1" /> [**Queues**](/services/queues) | Postgres | Message delivery |
| <Container className="inline w-4 h-4 mr-1" /> [**Sandbox**](/services/sandbox) | Compute + Storage | Isolated code execution |
| <Radio className="inline w-4 h-4 mr-1" /> [**Durable Streams**](/services/storage/durable-streams) | Storage | Persistent data streams |
| **Agent Runtime** | Compute | Agent execution environment |
| [**Observability**](/services/observability) | Warehouse | Logging, tracing, metrics |

These primitives use the Core Primitives but don't depend on each other horizontally. They only reach down the stack, never up.

### Application Services

The highest layer provides application-level services that combine multiple Platform Primitives:

| Service | Built On | Purpose |
| ------- | -------- | ------- |
| [**Authentication**](/services/authentication) | Database | User authentication and sessions |
| [**Webhooks**](/services/webhooks) | Queues + Compute | Receive external events |
| [**Schedules**](/services/schedules) | Queues + Compute | Cron-based delivery |
| [**Email**](/services/email) | Webhooks + Queues | Inbound and outbound email |
| [**Coder**](/services/coder) | Sandbox + Storage | Coding sessions and replay data |
| [**Web Analytics**](/services/observability/web-analytics) | OLAP Warehouse | Frontend analytics |

For example, an inbound email service works like this:
1. Email arrives at the Agentuity email service
2. The email is processed by a preconfigured webhook
3. An event is placed on the queue
4. This triggers the Agent Runtime where you can process the email
5. Store the email in Storage for long-term retention

Each service is composed from lower-level primitives rather than built from scratch.

## Why This Matters

<span className="text-cyan-800 dark:text-cyan-500 font-semibold">Composability</span>: Higher-level services are built from lower-level primitives. Need a new capability? Combine existing primitives rather than building from scratch.

<span className="text-cyan-800 dark:text-cyan-500 font-semibold">Portability</span>: Because core primitives use standard protocols, the underlying infrastructure can be swapped.

<span className="text-cyan-800 dark:text-cyan-500 font-semibold">Reliability</span>: Services build on primitives like Postgres and S3 instead of each service inventing its own storage layer.

<span className="text-cyan-800 dark:text-cyan-500 font-semibold">Agentic</span>: The same service boundaries that developers inspect can also give agents context about state, execution, and delivery.
