Call Agentuity services (key-value, AI Gateway, queues) from Next.js App Router route handlers, then package and deploy through `agentuity build`.

## Create a Starter

The quickest way to start is with the Agentuity CLI:

```bash
bun create agentuity@alpha --name my-next-app --framework nextjs
cd my-next-app
```

The starter includes a working translation demo: a React page that calls an API route, which uses `KeyValueClient` for session history and the OpenAI SDK routed through the AI Gateway. The key files:

| File | Purpose |
|------|---------|
| `src/app/page.tsx` | Client UI that calls the API route |
| `src/app/api/translate/route.ts` | Route handler: AI Gateway + KV history |
| `package.json` | `dev`, `build`, and `deploy` scripts pre-wired |

## Add to an Existing App

Install the CLI as a dev dependency, then import the project:

```bash
bun add -d @agentuity/cli@alpha
agentuity project import --validate-only   # dry run: checks config only
agentuity project import                   # registers the project and writes agentuity.json
```

`agentuity project import` writes the local project metadata that `agentuity deploy` expects. Run it once before the first deploy.

## Service Client Example

Route handlers use standalone service clients. They do not need an Agentuity-owned router or `createApp()`.

```bash
bun add @agentuity/keyvalue@alpha
```

```typescript title="src/app/api/notes/route.ts"
import { KeyValueClient } from '@agentuity/keyvalue';
import { NextResponse } from 'next/server';

interface Note {
	readonly id: string;
	readonly text: string;
	readonly createdAt: string;
}

// Instantiated once at module load; reads AGENTUITY_SDK_KEY from the environment
const kv = new KeyValueClient(); // [!code highlight]

export async function POST(request: Request): Promise<NextResponse> {
	const body: unknown = await request.json();

	if (typeof body !== 'object' || body === null || !('text' in body)) {
		return NextResponse.json({ error: 'text is required' }, { status: 400 });
	}

	const { text } = body;
	if (typeof text !== 'string' || !text.trim()) {
		return NextResponse.json({ error: 'text must be a non-empty string' }, { status: 400 });
	}

	const note: Note = {
		id: crypto.randomUUID(),
		text: text.trim(),
		createdAt: new Date().toISOString(),
	};

	await kv.set('notes', note.id, note, { ttl: 60 * 60 * 24 * 7 }); // 7-day TTL // [!code highlight]

	return NextResponse.json({ note });
}

export async function GET(request: Request): Promise<NextResponse> {
	const { searchParams } = new URL(request.url);
	const id = searchParams.get('id');

	if (!id) {
		return NextResponse.json({ error: 'id query param is required' }, { status: 400 });
	}

	const result = await kv.get<Note>('notes', id); // [!code highlight]

	if (!result.exists) {
		return NextResponse.json({ error: 'not found' }, { status: 404 });
	}

	// result.data is typed as Note because of the generic
	return NextResponse.json({ note: result.data });
}
```

`KeyValueClient` reads `AGENTUITY_SDK_KEY` from the environment. Run the app with `agentuity dev` to have the key injected automatically.

## AI Gateway Example

`agentuity dev` injects `OPENAI_API_KEY` and `OPENAI_BASE_URL` so the OpenAI SDK routes calls through the AI Gateway. Use `@agentuity/schema` to validate input at the boundary.

```bash
bun add openai @agentuity/schema@alpha
```

```typescript title="src/app/api/chat/route.ts"
import { s } from '@agentuity/schema';
import OpenAI from 'openai';
import { NextResponse } from 'next/server';

const requestSchema = s.object({
	message: s.string(),
	model: s.optional(s.string()),
});

// Reads OPENAI_API_KEY and OPENAI_BASE_URL from the environment
// agentuity dev injects both so calls go through the AI Gateway
const openai = new OpenAI(); // [!code highlight]

export async function POST(request: Request): Promise<NextResponse> {
	const body: unknown = await request.json();
	const parsed = requestSchema.safeParse(body); // [!code highlight]

	if (!parsed.success) {
		return NextResponse.json({ error: 'message is required' }, { status: 400 });
	}

	const { message, model = 'gpt-5.4-nano' } = parsed.data;

	const completion = await openai.chat.completions.create({ // [!code highlight]
		model,
		messages: [{ role: 'user', content: message }],
	});

	return NextResponse.json({
		reply: completion.choices[0]?.message?.content ?? '',
		tokens: completion.usage?.total_tokens ?? 0,
		model,
	});
}
```

<Callout type="tip" title="Keep handlers in app/api/**/route.ts">
Agentuity does not require `createApp()` or an Agentuity-owned router for Next.js projects. Standard App Router route handlers work as-is.
</Callout>

## Run Locally

Start the app with `agentuity dev`, which injects `AGENTUITY_SDK_KEY`, `OPENAI_API_KEY`, and `OPENAI_BASE_URL` into the Next.js process:

```bash
agentuity dev
```

Smoke-test the route:

```bash
curl http://127.0.0.1:3000/api/chat \
  -H "content-type: application/json" \
  -d '{"message":"Hello"}'
```

## Validate Before Deploy

Run the Next.js build first, then the Agentuity build. The Agentuity build produces `.agentuity/launch.json` with the start command for the deployed container.

```bash
bun run build
agentuity build
cat .agentuity/launch.json   # verify processes[0].command is "node server.js"
```

The `agentuity build` adapter sets `NEXT_PRIVATE_STANDALONE=true` at build time so Next.js produces `.next/standalone/`. Adding explicit `output: 'standalone'` to `next.config.ts` is safer: it works regardless of the adapter's env injection and makes the intent visible in your config file.

```typescript title="next.config.ts"
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
	output: 'standalone', // produces .next/standalone/ with a minimal server.js
};

export default nextConfig;
```

With standalone output, `agentuity build` copies the standalone server, `.next/static/`, and `public/` into the output directory, and sets the launch command to `node server.js`.

If `agentuity build` cannot find the local `next` binary, add `node_modules/.bin` to `PATH`:

```bash
PATH="$(pwd)/node_modules/.bin:$PATH" agentuity build
```

## Common Gotchas

| Symptom | Check |
|---------|-------|
| Service client returns 401 or auth errors | Run with `agentuity dev`, or set `AGENTUITY_SDK_KEY` manually |
| OpenAI calls hit the real provider instead of the AI Gateway | `OPENAI_BASE_URL` is only injected by `agentuity dev`; see [AI Gateway](/services/ai-gateway) for how env injection works |
| Anthropic SDK calls bypass the AI Gateway | Verify `ANTHROPIC_API_KEY` and `ANTHROPIC_BASE_URL` are set; `agentuity dev` injects both. See [AI Gateway](/services/ai-gateway) |
| `agentuity build` fails with "next: command not found" | Prefix with `PATH="$(pwd)/node_modules/.bin:$PATH"` |
| Deploy starts `next start` instead of `node server.js` | Add [`output: 'standalone'`](https://nextjs.org/docs/app/api-reference/config/next-config-js/output) to `next.config.ts`, rebuild, then inspect `.agentuity/launch.json` |
| `.next/standalone` is empty after build | Confirm Next.js version is 12+; older versions do not support standalone output |
| Files outside the app root are missing in the standalone bundle | Set `outputFileTracingRoot` in `next.config.ts` to include monorepo paths |
