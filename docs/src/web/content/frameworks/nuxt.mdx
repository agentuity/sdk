Start with a normal [Nuxt](https://nuxt.com/docs) app. Agentuity adds service clients, local development support, and deploy validation around Nitro server routes and build output.

## Create a Starter

```bash
npm create agentuity@next -- --name my-nuxt-app --framework nuxt
cd my-nuxt-app
```

The starter runs `nuxi init`, adds `@agentuity/cli`, a `deploy` script, and an optional AI example. It uses Nuxt's `server/api/` convention for server routes, the same shape documented by Nuxt's own server directory guide.

If you choose the AI example, the key files are:

| File | Purpose |
|------|---------|
| `server/api/translate.post.ts` | Nitro route that handles `POST /api/translate` |
| `app/app.vue` | UI that calls the API route with `$fetch` |
| `nuxt.config.ts` | Nuxt configuration in the normal Nuxt shape |

## Import an Existing App

For an existing Nuxt app, add the CLI and import the project:

```bash
npm install -D @agentuity/cli@next
npx agentuity project import --validate-only
npx agentuity project import
```

`npm install -D` installs the CLI as a project-local dev dependency, not a global install. Use `npx` to run that local CLI. For Bun, pnpm, and Yarn equivalents, see [Local versus global CLI](/get-started/installation#local-versus-global-cli).

`agentuity project import` registers the app and writes the local project metadata that `agentuity deploy` expects. Run it once before the first deploy for existing apps.

<Callout type="tip" title="Existing app?">
See [Add Agentuity to an existing app](/get-started/import-existing-app) for validation, import, the `Invalid project folder` deploy case, and first deploy.
</Callout>

## What Agentuity adds

| Area | Nuxt keeps | Agentuity adds |
| --- | --- | --- |
| routing | Nitro handlers in `server/api/` | service clients imported in server-only files |
| local dev | `nuxt dev` | `agentuity dev` supplies service credentials and supported provider SDK wiring |
| build | Nitro output under `.output/` | `agentuity build` runs the build and packages launch metadata |
| deploy | the Nitro server entry | `agentuity deploy` ships the packaged app |

## Add a Service Client and AI Gateway Call

Use standalone service clients directly from Nitro routes. Files under `server/api/` are automatically prefixed with `/api`, and the `.post.ts` suffix limits this example to `POST` requests.

The route below intentionally uses the OpenAI SDK to show provider SDK env wiring. For generic model calls, use `AIGatewayClient` as in the starter or see [AI Gateway](/services/ai-gateway#choose-the-model-path).

```bash
npm install @agentuity/keyvalue@next openai arktype
```

```typescript title="server/api/translate.post.ts"
import { KeyValueClient } from '@agentuity/keyvalue';
import OpenAI from 'openai';
import { type } from 'arktype';
import { defineEventHandler, getCookie, readBody, setCookie, setResponseStatus } from 'h3';

const HISTORY_NAMESPACE = 'translation-history';
const SESSION_COOKIE = 'agentuity_session';
const SESSION_TTL_SECONDS = 60 * 60 * 24 * 30;

interface HistoryEntry {
  readonly model: string;
  readonly sessionId: string;
  readonly text: string;
  readonly timestamp: string;
  readonly tokens: number;
  readonly toLanguage: string;
  readonly translation: string;
}

interface HistoryState {
  readonly history: readonly HistoryEntry[];
  readonly translationCount: number;
}

// Validate the request body at the boundary before using any values
const requestSchema = type({
  text: 'string',
  toLanguage: 'string',
  'model?': 'string',
});

const kv = new KeyValueClient(); // [!code highlight]

export default defineEventHandler(async (event) => {
  const rawBody: unknown = await readBody(event);
  const parsed = requestSchema(rawBody);

  if (parsed instanceof type.errors) {
    setResponseStatus(event, 400);
    return { error: 'text and toLanguage are required' };
  }

  const input = parsed;
  const model = input.model ?? process.env.OPENAI_MODEL;
  if (!model) {
    setResponseStatus(event, 500);
    return { error: 'OPENAI_MODEL is required' };
  }

  // Instantiate after validation so plain Nuxt builds do not need provider env at module load.
  const openai = new OpenAI(); // [!code highlight]

  // Read or create a session cookie so history is scoped per browser session
  const sessionId = getCookie(event, SESSION_COOKIE) ?? crypto.randomUUID();
  setCookie(event, SESSION_COOKIE, sessionId, {
    httpOnly: true,
    maxAge: SESSION_TTL_SECONDS,
    path: '/',
    sameSite: 'lax',
    // set secure when running in production
    secure: process.env.NODE_ENV === 'production',
  });

  const completion = await openai.chat.completions.create({ // [!code highlight]
    model,
    messages: [
      {
        role: 'user',
        content: `Translate to ${input.toLanguage}:\n\n${input.text}`,
      },
    ],
  });

  const translation = completion.choices[0]?.message?.content ?? '';

  const tokens = completion.usage?.total_tokens ?? 0;

  // Append to the per-session history stored in KV, keeping the last 5 entries
  const previous = await kv.get<HistoryState>(HISTORY_NAMESPACE, sessionId);
  const history = [
    ...(previous.exists ? previous.data.history : []),
    {
      model,
      sessionId,
      text: input.text,
      timestamp: new Date().toISOString(),
      tokens,
      toLanguage: input.toLanguage,
      translation,
    },
  ].slice(-5);
  const translationCount = (previous.exists ? previous.data.translationCount : 0) + 1;

  await kv.set(HISTORY_NAMESPACE, sessionId, { history, translationCount }, { ttl: SESSION_TTL_SECONDS }); // [!code highlight]

  return {
    translation,
    history,
    tokens,
    model,
    translationCount,
  };
});
```

`KeyValueClient` reads `AGENTUITY_SDK_KEY` from the environment. Run with `agentuity dev` for local development so the linked project key is available to Nitro routes.

Set `OPENAI_MODEL` in `.env` to the provider model ID for this OpenAI SDK example. Use the [AI Gateway model catalog](/services/ai-gateway#model-catalog) or your provider's model list before choosing a value.

## Call from the Frontend

Call the Nitro route from `app/app.vue` using Nuxt's built-in `$fetch`:

```vue title="app/app.vue"
<script setup lang="ts">
const text = ref('Welcome to Agentuity');
const toLanguage = ref('Spanish');
const translation = ref('');
const history = ref<Array<{ text: string; translation: string; toLanguage: string }>>([]);

async function translate(): Promise<void> {
  const result = await $fetch<{
    translation: string;
    history: typeof history.value;
  }>('/api/translate', {
    method: 'POST',
    body: { text: text.value, toLanguage: toLanguage.value },
  });

  translation.value = result.translation;
  history.value = result.history;
}
</script>

<template>
  <div>
    <textarea v-model="text" />
    <select v-model="toLanguage">
      <option>Spanish</option>
      <option>French</option>
      <option>German</option>
    </select>
    <button @click="translate()">Translate</button>
    <p v-if="translation">{{ translation }}</p>
  </div>
</template>
```

## Run Locally

Run through Agentuity. When the linked project key is available, the CLI supplies `AGENTUITY_SDK_KEY` and supported provider SDK env wiring to the Nuxt process:

```bash
agentuity dev
```

Smoke-test the Nitro route directly:

```bash
curl http://localhost:3000/api/translate \
  -H "content-type: application/json" \
  -d '{"text":"Hello","toLanguage":"Spanish"}'
```

## Deployed Environment Variables

Configure the variables your deployed app needs. `agentuity dev` can provide the Agentuity SDK key and provider SDK wiring locally, but deployed apps should set the same values through project env or secrets.

| Variable | Used by |
| --- | --- |
| `AGENTUITY_SDK_KEY` | Agentuity service clients and `@agentuity/aigateway` |
| `OPENAI_MODEL` | provider SDK env-wiring example routes that call the OpenAI SDK |
| `OPENAI_API_KEY`, `OPENAI_BASE_URL` | OpenAI SDK through AI Gateway env wiring |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL` | Anthropic SDK through the AI Gateway |
| `GROQ_API_KEY`, `GROQ_BASE_URL` | Groq SDK through the AI Gateway |
| `DATABASE_URL` | database Nitro routes |
| `AWS_*` | object storage Nitro routes; see [Object Storage](/services/storage/object) for exact variables |

## Validate Before Deploy

Run the framework build when you want Nuxt-only feedback, then run the Agentuity build. `agentuity build` runs the framework build during packaging and writes `.agentuity/launch.json`.

```bash
npm run build
npx agentuity build
```

Nuxt is detected as its own framework (`nuxt`, `nuxt3`, `nuxt-edge`, or `nuxt-nightly` in dependencies). The build adapter packages the Nitro output. Verify the metadata points at the right paths:

```bash
cat .agentuity/launch.json
```

The Nitro build produces two output directories:

| Path | Contents |
|------|----------|
| `.output/server` | Nitro server bundle, entry is `server/index.mjs` |
| `.output/public` | Static assets for CDN or edge delivery |

`launch.json` must reference the `server/index.mjs` entry inside `.output/server`. If it points at a static `_serve.js` helper, the packaged output is not serving Nitro routes.

Deploy only after the framework build, Agentuity build, and a local packaged validation of `/` and one Nitro route pass:

```bash
agentuity deploy --confirm
```

## Common Gotchas

| Symptom | Check |
|---------|-------|
| Route exists locally but returns 404 after deploy | Confirm the file is under [`server/api/`](https://nuxt.com/docs/guide/directory-structure/server), not `server/routes/`; only `server/api/` gets the `/api` prefix |
| `$fetch('/api/...')` works locally but 404s after deploy | Inspect `.agentuity/launch.json`: `processes[0].command` must run `.output/server/index.mjs` |
| Service client returns auth errors | Run with `agentuity dev` or set `AGENTUITY_SDK_KEY` in the environment |
| OpenAI calls bypass Agentuity AI Gateway | Verify `OPENAI_BASE_URL` points at the AI Gateway and a local `.env` is not intentionally overriding provider SDK wiring |
| Anthropic or Groq SDK calls bypass the AI Gateway | Verify the matching `*_BASE_URL` points at the AI Gateway. See [AI Gateway](/services/ai-gateway) |
| Server credentials leak to the browser | Keep `KeyValueClient` and `OpenAI` instantiation in `server/api/` or other server-only files; Nitro does not bundle server files into the client |
| Cookie flags rejected by browser | `secure: true` requires HTTPS; for local testing use `secure: process.env.NODE_ENV !== 'development'` |
