Customize how your project is built using `vite.config.ts` in your project root. Add Vite plugins for frontend builds, define build-time constants, or bundle extra files into your deployment.

## Basic Configuration

```typescript
import { defineConfig } from 'vite';

export default defineConfig({
  // Configuration options here
});
```

## Configuration Options

### plugins

Add Vite plugins for frontend builds (`src/web/`). Plugins run after built-in plugins (React, environment variables).

```typescript
import { defineConfig } from 'vite';
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  plugins: [tailwindcss()],
});
```

See the [Vite plugin documentation](https://vitejs.dev/plugins/) for available plugins.

<Callout type="info" title="Frontend Only">
Vite plugins apply to frontend builds only. Server code is bundled separately with Bun.
</Callout>

### define

Replace identifiers with constant values at build time. Values must be JSON-stringified.

```typescript
import { defineConfig } from 'vite';

export default defineConfig({
  define: {
    'API_VERSION': JSON.stringify('v2'),
    '__DEV__': JSON.stringify(false),
  },
});
```

<Callout type="warning" title="Reserved Keys">
These keys are set by the build system and will override any user-defined values:
- `import.meta.env.AGENTUITY_PUBLIC_*` (Agentuity internal variables)
- `process.env.NODE_ENV`
</Callout>

### workbench

Workbench is now configured via `createApp()` in your `app.ts`, not in the build config. See [Testing with Workbench](/agents/workbench) for usage.

```typescript
import { createApp } from '@agentuity/runtime';

const app = await createApp({
  workbench: true, // Enables at /workbench
});

export default app;
```

Omit the `workbench` option to disable Workbench.

### bundle

Include additional files in your deployment package using glob patterns. Use this to ship data files, prompt templates, configuration, or other non-code assets alongside your agents.

```typescript
import { defineConfig } from 'vite';

export default defineConfig({
  bundle: ['prompts/**', 'data/*.json', 'models/weights.bin'],
});
```

Files are copied into the build output **before** the build runs, preserving their relative directory structure from the project root. If any bundled file path conflicts with a build output path, the build output takes priority.

**Accessing bundled files at runtime:**

```typescript
// src/agents/assistant/index.ts
const systemPrompt = await Bun.file('prompts/system.md').text();
const data = await Bun.file('data/knowledge-base.json').json();
```

#### Automatic Filtering

Two layers of filtering protect against accidentally bundling sensitive or unnecessary files:

**Hard exclusions** — always skipped, cannot be overridden:
- `.agentuity/` — Build output directory
- `node_modules/` — Dependencies
- `.git/` — Git repository data
- `.env`, `.env.*` — Environment files containing secrets

**`.gitignore` filtering** — files ignored by your `.gitignore` are automatically excluded. This means build artifacts, editor files, OS files, and anything else you've gitignored won't be bundled. If the project is not a git repository, this layer is skipped.

<Callout type="info" title="Common Use Cases">
- **Prompt templates**: Bundle Markdown or text files used as LLM prompts
- **Data files**: Include JSON, CSV, or other data your agents need
- **ML models**: Ship model weights or configuration files
- **Static configuration**: Include YAML, TOML, or other config files
</Callout>

## Environment Variables

Environment variables with these prefixes are available in frontend code:

| Prefix | Description |
|--------|-------------|
| `VITE_*` | Standard Vite convention |
| `AGENTUITY_PUBLIC_*` | Agentuity convention |
| `PUBLIC_*` | Short form |

```typescript
// .env.local
AGENTUITY_PUBLIC_API_URL=https://api.example.com

// src/web/App.tsx
const apiUrl = import.meta.env.AGENTUITY_PUBLIC_API_URL;
```

<Callout type="warning" title="Security">
Public environment variables are bundled into frontend code and visible in the browser. Never put secrets or API keys in public variables.
</Callout>

## Build Architecture

Agentuity uses a hybrid build system:

| Component | Tool | Output |
|-----------|------|--------|
| Frontend (`src/web/`) | Vite | `.agentuity/client/` |
| Workbench | Vite | `.agentuity/workbench/` |
| Server (agents, routes) | Bun | `.agentuity/app.js` |

This separation allows Vite's optimizations for frontend (HMR, tree-shaking, CSS processing) while using Bun's fast bundling for server code.

For details on how these components interact during development, see [Dev Server Architecture](/reference/cli/development#dev-server-architecture).

## Full Example

```typescript title="vite.config.ts"
import { defineConfig } from 'vite';
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  // Vite plugins for frontend
  plugins: [tailwindcss()],

  // Build-time constants
  define: {
    'APP_VERSION': JSON.stringify('1.0.0'),
  },

  // Extra files to include in deployment
  bundle: ['prompts/**', 'data/*.json'],
});
```
